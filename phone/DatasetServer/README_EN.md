# DatasetServer — XR Dataset Chunk Upload Service

Receives recorded data chunks from the VR headset via HTTP multipart upload.

## System Workflow

```
VR Headset Records Chunks → Auto-upload on chunk ready → PC DatasetServer (:9000) → dataset/<chunk_name>/
                                ↑
                        Flutter Control Panel BLE: set URL / chunk duration
```

The VR headset automatically splits recorded datasets into independent subdirectories based on chunk duration. Each chunk is automatically uploaded via HTTP multipart as soon as it completes. Chunk duration and upload URL can be configured via the Flutter control panel's Settings page.

## Requirements

- **Python 3.6+** (no third-party dependencies — standard library only)
- Windows / Linux / macOS

On Windows / macOS, the dataset receive service is integrated into the EgoVision PC app, so no separate launcher script is needed (controlled by an in-app toggle, off by default); on Linux, run the scripts in this directory with the system Python.

## Quick Start

### Windows / macOS

Integrated into the EgoVision PC app (no separate launcher script required).

### Linux
```bash
chmod +x start_server.sh
./start_server.sh --port 9000
```

### Run with Python Directly
```bash
python3 server.py --port 9000 --dir ./received_chunks
```

| Argument | Default | Description |
|----------|---------|-------------|
| `--port` | `9000` | HTTP listen port |
| `--dir` | `dataset/` (under the script's directory) | Directory to save uploaded chunks |
| `--timeout` | `60` | Socket idle timeout in seconds, used to abort dead-connection uploads |

After startup, the terminal prints all accessible URLs on this machine. Enter one of them as the "Chunk Upload Address" in the Flutter control panel's Settings page.

## API Reference

### Overview

- **Protocol**: HTTP/1.1
- **Default Port**: 9000
- **Format**: multipart/form-data
- **Max Body Size**: 5 GB (only enforced for requests with a fixed `Content-Length`; the VR headset actually uploads with chunked encoding, which bypasses this limit and is read into memory in full)
- **CORS**: Enabled

---

### 1. Welcome Page / API Docs

**`GET /`**

Returns plain-text API documentation and a list of local addresses. Can be viewed in a browser.

---

### 2. Health Check

**`GET /api/health`**

Response:
```json
{
  "status": "ok",
  "received_chunks": 5,
  "uptime_seconds": 3600
}
```

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | Always `"ok"` |
| `received_chunks` | int | Total chunks received since startup |
| `uptime_seconds` | int | Server uptime in seconds |

---

### 3. Upload Chunk

**`POST /api/upload`**

Upload a chunk subdirectory recorded by the VR headset.

#### Request

- **Content-Type**: `multipart/form-data`
- **Fields:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `chunk_name` | string | Yes | Chunk directory name, format `<SN>_YYYYMMDD_HHMMSS` (`SN` = device serial prefix to distinguish devices; falls back to `YYYYMMDD_HHMMSS` when SN is absent) |
| `files` | file | Yes | Files within the chunk; repeat for multiple files |

#### Chunk Contents

Each chunk contains the following files (generated by VR recording):

| File | Description |
|------|-------------|
| `rgb.mp4` | RGB camera video (H.265) |
| `tracking.mp4` | Tracking camera video (H.265) |
| `ctrl.mp4` | Ctrl camera video (H.265) |
| `audio.m4a` | Audio recording |
| `rgb_metainfo.csv` | RGB frame metadata (timestamps, etc.) |
| `tracking_metainfo.csv` | Tracking frame metadata |
| `ctrl_metainfo.csv` | Ctrl frame metadata |
| `audio_metainfo.csv` | Audio frame metadata |
| `accel.csv` | Accelerometer data |
| `gyro.csv` | Gyroscope data |
| `head_pose.csv` | Head pose data |
| `hand_tracking.csv` | Hand tracking data |
| `controller_poses.csv` | Controller pose data |
| `camera_params_rgb.json` | RGB camera intrinsics/extrinsics |
| `camera_params_tracking.json` | Tracking camera intrinsics/extrinsics |
| `camera_params_ctrl.json` | Ctrl camera intrinsics/extrinsics |
| `imu_calibration.json` | IMU calibration (bias / scale factor / non-orthogonality / time alignment / noise) |

#### Example (curl)

```bash
curl -F "chunk_name=SN_20260630_143000" \
     -F "files=@rgb.mp4;type=application/octet-stream" \
     -F "files=@tracking.mp4;type=application/octet-stream" \
     -F "files=@accel.csv;type=application/octet-stream" \
     http://192.168.1.100:9000/api/upload
```

#### Raw HTTP Request Format

```
POST /api/upload HTTP/1.1
Host: 192.168.1.100:9000
Content-Type: multipart/form-data; boundary=----ChunkUpload

------ChunkUpload
Content-Disposition: form-data; name="chunk_name"

20260630_143000
------ChunkUpload
Content-Disposition: form-data; name="files"; filename="rgb.mp4"
Content-Type: application/octet-stream

<binary data of rgb.mp4>
------ChunkUpload
Content-Disposition: form-data; name="files"; filename="tracking.mp4"
Content-Type: application/octet-stream

<binary data of tracking.mp4>
------ChunkUpload
Content-Disposition: form-data; name="files"; filename="accel.csv"

<text content of accel.csv>
------ChunkUpload--
```

#### Response (Success)

```json
{
  "status": "ok",
  "chunk_name": "SN_20260630_143000",
  "file_count": 17,
  "total_bytes": 123456789
}
```

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | `"ok"` on success |
| `chunk_name` | string | Chunk directory name |
| `file_count` | int | Number of files saved |
| `total_bytes` | int | Total bytes written |

#### Error Response

```json
{
  "error": "missing chunk_name field"
}
```

#### Status Codes

| Code | Meaning |
|------|---------|
| 200 | Upload successful |
| 400 | Bad request (missing fields, not multipart, etc.) |
| 404 | Endpoint not found |
| 409 | Concurrent upload conflict (EgoVision PC built-in version only; one upload at a time) |
| 413 | Payload too large (>5 GB, fixed `Content-Length` requests only; chunked uploads never trigger this) |

During upload, the terminal displays real-time progress including percentage, transfer speed, and estimated time remaining (fixed `Content-Length` requests only; the VR headset's chunked uploads only print a "receiving" line and a final summary).

## Storage Structure

Uploaded chunks are saved to the directory specified by `--dir` (default `dataset/` under the script's directory), in subdirectories named by `chunk_name`:

```
dataset/
├── SN_20260630_143000/
│   ├── rgb.mp4
│   ├── tracking.mp4
│   ├── ctrl.mp4
│   ├── audio.m4a
│   ├── rgb_metainfo.csv
│   ├── tracking_metainfo.csv
│   ├── ctrl_metainfo.csv
│   ├── audio_metainfo.csv
│   ├── accel.csv
│   ├── gyro.csv
│   ├── head_pose.csv
│   ├── hand_tracking.csv
│   ├── controller_poses.csv
│   ├── camera_params_rgb.json
│   ├── camera_params_tracking.json
│   ├── camera_params_ctrl.json
│   └── imu_calibration.json
└── SN_20260630_150000/
    └── ...
```

> The EgoVision PC built-in version uses a different layout: two levels keyed by device SN — `<Documents>/XRCameraControl/dataset/<sn>/<YYYYMMDD_HHMMSS>/` (the SN prefix is stripped from chunk_name).

## EgoVision PC Built-in Version Differences

The upload service built into the EgoVision PC app (Windows / macOS) is protocol-compatible with this Python version, but behaves differently:

- `GET /api/health` returns only `{"status": "ok"}` (no `received_chunks` / `uptime_seconds`)
- The upload success response includes an extra `delete_after_upload` field, which the VR side uses to decide whether to delete the local chunk
- Storage layout is `dataset/<sn>/<timestamp>/` (see above)
- Concurrent uploads are rejected with 409; files are streamed to disk (no 5 GB limit, chunked bodies are not buffered wholly in memory)

---

## Security Notes

- `chunk_name` is sanitized with `os.path.basename`; filenames have their separators normalized, leading `/` stripped, and `.`/`..`/empty segments removed (relative subdirectory levels are preserved), with an absolute-path prefix re-check after writing — two layers of path-traversal protection
- Request body limited to 5 GB (fixed `Content-Length` requests only; chunked uploads are unlimited and read into memory in full)
- This service is designed for **local network** use — no authentication or TLS
- For public deployment, add authentication and TLS at a reverse proxy layer

---

## Custom Implementation Guide

To implement a DatasetServer in your own language/framework, you only need to support the `POST /api/upload` endpoint described above. Core logic:

1. Parse `multipart/form-data` request body
2. Extract the `chunk_name` field as the subdirectory name
3. Extract each `files` field, save using its `filename` into the subdirectory
4. Return a JSON success/failure response
